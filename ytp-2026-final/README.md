# YTP 2026（第 11 屆少年圖靈計畫）複賽：我負責的三題

三人一隊、四小時。我負責第 1、6、11 題：第 1 題在比賽中 AC，第 6、11 題是賽後補完的。

> 這個資料夾的 README 與效能紀錄表在 AI 工具協助下整理；正解程式碼取自我的題解。

| 題號 | 題目 | 檔案 | 核心做法 | 複雜度 | 狀態 |
|---|---|---|---|---|---|
| 1 | 角色決鬥 | `p01_battle.cpp` | 冷卻相同的招式一定在同一回合施放，先依冷卻分組，再用類似篩法的方式累加每回合傷害，逐回合模擬 | 約 5×10⁷ 次運算；兩個 int 陣列估算約 80 MB（上限 1024 MB） | 賽中 AC |
| 6 | 小 Y 與小 P 的大冒險 | `p06/sol.cpp` | 對答案（路徑最大邊權）二分搜尋；邊權大於答案的邊要花 1 個法寶，用 0-1 BFS 求最少法寶數 | O((N+M) log M) | 賽後補完 |
| 11 | 五維西洋棋 | `p11/sol.cpp` | 每一維排序後，滿足該維條件的點是一段連續區間；每 64 格存一份前綴 bitset，區間 bitset 由兩個檢查點 XOR 再補翻至多 63 個位元，五維 AND 後 popcount | O(5·n²/64) | 賽後補完 |

## 對拍（用暴力解檢查正解）

第 6、11 題的資料夾裡各有四個檔案：

| 檔案 | 用途 |
|---|---|
| `sol.cpp` | 正解 |
| `brute.cpp` | 暴力解：第 6 題用 DFS 枚舉 1 到 N 的所有簡單路徑，取路徑上第 k+1 大的邊權；第 11 題用 O(n²) 兩兩比較五個維度的最大差 |
| `gen.py` | 隨機測資產生器，參數是亂數種子 |
| `stress.sh` | 編譯兩支程式，跑指定組數的隨機測資並比對輸出；不一致時停下來並保留那組測資 |

```bash
bash p06/stress.sh 1000   # 輸出「通過 1000 組」
bash p11/stress.sh 1000
```

測資產生器刻意涵蓋的情況：

- 第 6 題：N 只有 2–6，邊權上限隨機取 3、10 或 10⁹（小上限會產生大量相同邊權），也會產生 1 和 N 不連通的圖（答案 −1）與法寶夠用的情況（答案 0）。
- 第 11 題：n 會落在 1–40、60–70、120–300 三個範圍，跨過 bitset 64 位元一塊的邊界；座標範圍取 ±3、±10 或 ±10⁹，前兩種會產生大量重複座標；k 會取到 0 與 2×10⁹，檢查 v ± k 的溢位。

比賽後寫題解時，第 1 題是用暴力模擬對拍 200 組，第 6 題是用「(節點, 已用法寶數) 的 Dijkstra」對拍 300 組，第 11 題是用 O(n²) 暴力對拍 200 組。這裡附的是整理作品集時整理成可重複執行的版本：第 6 題的暴力改用 DFS 枚舉路徑，和 Dijkstra 是兩種獨立的檢查方法。第 1 題的對拍程式沒有附上。

## 編譯與執行

```bash
g++ -O2 -std=c++17 -o p11/sol p11/sol.cpp
./p11/sol < input.txt
```

## 第 11 題的效能紀錄

量測方式：Linux，`g++ -O2 -std=c++17`，記憶體取 `/usr/bin/time -v` 的 Maximum resident set size（峰值）。

| n | 時間 | 峰值記憶體 |
|---|---|---|
| 3×10⁴ | 約 0.2 秒 | 約 15 MB |
| 10⁵（隨機座標） | 約 1.0–2.2 秒，依機器與 k 而不同；時限 3 秒，偏緊 | 107 MB |

- 估算：每一維約 (n/64)² 個 64 位元字，n = 10⁵ 時五維共約 100 MB，和實測的 107 MB 相符。
- k 取 0、10⁸、10⁹、2×10⁹ 時記憶體都一樣，只和 n 有關；時間在 k = 10⁸ 時最長。
- 題目敘述寫 n ≤ 3×10⁴，但子任務寫 n ≤ 10⁵，兩者不一致，所以我用 10⁵ 測

## 注意事項（節錄自我的題解）

- 第 1 題：招式第一次可施放是第 c 回合，不是第 1 回合；玩家 1 出手後要立刻檢查對手血量。
- 第 6 題：0 要放進候選答案（法寶夠多時答案為 0）；1 與 N 不連通時輸出 −1。
- 第 11 題：v ± k 最大 3×10⁹，必須用 long long；自己和自己也會被算到一次，最後要先減 n 再除以 2。
